Scenario reference

A scenario is an initial-condition / boundary-condition pair plus the grid geometry it needs. chromosphere::make_scenario maps a name to that pair; the name is the fourth positional argument to chromo_main and defaults to model_column. See Configuration reference for the full argument and environment-variable surface.

Which solver runs is decided by data, not by a flag: **a loaded Gamma1 table selects the release single-fluid solver**, and an empty one selects the historical two-fluid solver. model_column supplies the production table unconditionally; every other scenario never loads one. Each solver rejects the other's Grid, so the choice cannot be made by accident.

model_column — the release scenario

model_column means exactly one thing: the release solver. The scenario supplies GAMMA_TABLE=data/eos/gamma1_hydrogen_v1.dat unconditionally (only the path is overridable), so a model_column run is always a release run. It rejects ISO_GAMMA in make_scenario, and model_column_ic additionally rejects every historical two-fluid knob outright — ISO_GAMMA, ISO_TWO_FLUID, ISO_IONIZATION, ISO_COOLING, ISO_TRAC, ISO_CORONA, ISO_CHEAT, ISO_QFLUX, ISO_TBOOST, ISO_NUMERICAL_DIFFUSIVITY_MULT — rather than silently ignoring them. The driver separately rejects SINGLE_FLUID, ENABLE_TE and a finite-rate-ionization request. A release run therefore cannot be reconfigured into something else.

Field-line geometry. A single straight field line with B_imh = B_i = B_iph = 1 and d(1/B)/ds = 0 — constant area, so the flux-tube expansion source drops out. Gravity is on, with the potential phi_g(s) = g (h(s) - h_base) gauged to zero at the domain base. The domain runs from ISO_H_BASE = 1600 km to 1600 + ISO_DH = 2153 km. The mesh is the coarse-equivalent ISO_NS = 500 with static outer local refinement — ISO_REFINE_FACTOR = 4, ISO_REFINE_S_LO_KM = 500, ISO_REFINE_TRANSITION_KM = 20 — giving a fine band from 2100 km to the top and 661 actual cells. This is static local refinement generated once at IC time, not AMR.

Initial condition. The temperature is the Model C7 profile through the shape-preserving PCHIP interpolant c7_full_temperature_pchip, averaged over each cell rather than sampled at its centre, so refinement represents the same continuum thermal profile instead of shifting the top-cell datum. The total density is then re-integrated hydrostatically from the base, d ln p / dh = -g m_H / ((1 + x) k_B T), with the ionization fraction x taken from Saha at each step and the trapezoidal step iterated to a fixed point (tolerance 2e-13, at most 60 iterations, and it throws rather than proceeding if it fails to converge). Velocity is zero everywhere, so V ~ 0 is a clean discrete start and any later flow is conduction-driven. Cells are packed through mixture_pack_cell into U = (rho, rho u, E); x, n_e, n_HI and p_e are derived EOS diagnostics and are never stored.

Inner boundary (1600 km) — a mid-chromospheric truncation, not the photosphere. 1600 km is the height below which this solver's Saha/LTE equilibrium closure is not intended to be trusted. The real atmosphere continues below it and is deliberately outside the model. The two inner ghosts are a numerical closure for the MUSCL stencil, not a claim that LTE extends downward. The physical content of the boundary is exactly one statement: on the timescales resolved here the lower chromosphere behaves as a quasi-static stratified reservoir at the truncation temperature T_0, with v = 0. Concretely, both ghosts are Dirichlet in density and temperature and hold v = 0 exactly; their pressures come from a second-order trapezoidal, EOS-closed hydrostatic ladder stepping down from cell 0, p_{k+1} = p_k + ds * 0.5 * (rho_k + rho_{k+1}) * g with rho_{k+1} = rho_EOS(p_{k+1}, T_0) iterated to a fixed point (gamma_hse_rung_down). This is the same construction the outer face uses, so the two boundaries are discretely consistent. The reservoir values are captured once from the initial condition and are fixed thereafter. Separately and independently, the conduction stage imposes its own lower temperature condition, Dirichlet by default; ISO_INNER_T_NEUMANN=1 makes it Neumann (zero flux). Never describe this face as photospheric.

Outer boundary (2153 km). Subsonic outflow admits exactly one incoming characteristic, so exactly one condition may come from outside: a fixed reservoir back-pressure kOuterPRef, captured once one-sided-hydrostatically from the V = 0 reference top cell. Anchoring to a fixed reference rather than to a live interior cell is what makes the face well posed — a centred anchor on cell ns-2 extrapolates across the very cell it bounds and can invert the pressure gradient inside the transition region, while a one-sided anchor on the top cell makes pressure zero-gradient and lets the column drain out of the top. The first ghost therefore takes p = kOuterPRef (Dirichlet in pressure); the second comes from an EOS-closed trapezoidal hydrostatic rung above it. Ghost densities are closed by the EOS at (p_ghost, T_ghost). Temperature plays two roles that the release keeps explicitly separate, because ISO_HYDRO_T_DECOUPLE = 1 in the release preset: the conduction rows see a fixed 22,000 K Dirichlet wall at the physical outer face (ISO_T_TOP = 22000, applied through Grid::outer_conduction_temperature), while the hydro ghost temperature is a zero-gradient extrapolation of the live top cell, so the outer face does not additionally pin the thermal/entropy state. Velocity is Mach-capped outflow: the ghost copies the top-cell velocity, clamped to |V| <= ISO_VCAP * c_s with ISO_VCAP = 0.1 and c_s from the Gamma1 sound speed.

Active physics. Hydro plus implicit backward-Euler physical conduction only. The release timestep is U^n -> explicit MUSCL-Hancock/Roe hydro -> U* -> implicit physical conduction -> U^{n+1}, composed by first-order Lie splitting. TRAC, beam heating, volumetric coronal heating, radiative cooling and artificial/numerical conduction are not release physics and are not present in that path, not even behind default-off flags — numerical_diffusivity_per_length is set to 0 structurally, enable_trac, enable_vacuum_floor, enable_ionization, enable_radiative_cooling, enable_beam_heating, enable_coronal_heating, impose_outer_heat_flux and enable_Te are all false. The release is also reference-free: Grid::eq_wb is false on this path and no frozen global hydrostatic residual is subtracted. Numerics set by the scenario, with no environment variable required: roe_characteristic_flux, pressure_reconstruct, well_balanced, log_reconstruct, mc3_limiter with limiter_beta = 2. ISO_RIEMANN=rusanov and ISO_RECONSTRUCTION=lnrho-v-lnt exist only as reference overrides for regression and controlled comparison; never use them in production. See Numerical method.

Source files. scenarios/model_column.hpp, scenarios/model_column.cpp, scenarios/mesh.hpp, scenarios/mesh.cpp, the C7 table helpers in scenarios/model_c7.cpp, and src/single_fluid/.

model_gentle — the historical two-fluid column

model_gentle is the historical two-fluid research preset on the same IC/BC implementation as model_column — one file, scenarios/model_column.cpp, serves both. The two never cross solvers: model_gentle never loads a Gamma1 table, so it always selects the seven-row two-fluid solver with a fixed adiabatic index, finite-rate ionization, a radiative sink and TRAC. Nothing a user can set moves either scenario across that line.

Geometry and domain. Same straight field line, B = 1, gravity on. The preset sets ISO_H_BASE = 1003 km — the model_c7 validated floor — because the Stage-E n^2 reaction channels and the radiative loss overflow float32 at photospheric density. ISO_CORONA = 1 extends the top into a resolved ~1 MK corona (ISO_CORONA_TOP_KM, default 10,000 km), and ISO_NS = 600.

Initial condition. The same C7 temperature and ionization-fraction profile with the total density re-integrated hydrostatically, but closed with the fixed adiabatic index Grid::gamma_mono (default 5/3, tunable through ISO_GAMMA) rather than the Saha/Gamma1 closure. The Route-B photoionization rate is inverted over the active Stage-E network so the C7 profile is a fixed point of it.

Boundaries. Inner face: the legacy first-order ladder, p_ghost = p_0 + k rho_0 g ds with rho proportional to p at fixed T_0, V = U = 0, densities Dirichlet. Outer face: the same fixed-back-pressure hydrostatic ladder and Mach-capped outflow (ISO_VCAP = 0.1) as the release, with ghost-temperature jump factors ISO_TJUMP_A/ISO_TJUMP_B defaulting to 1 — with the corona resolved inside the domain the ghost simply extends it — and the reference top temperature captured from the initial condition rather than imposed absolutely.

Active physics. Two-fluid ion/neutral evolution, the finite-rate Stage-E ionization/recombination network, the radiative sink, TRAC (automatically on because cooling is on, trac_T_chrom = 2e4 K), the vacuum/positivity floor, and conduction. This path keeps the frozen equilibrium reference: Grid::eq_wb is true and eq_state is the initial condition, because the two-fluid solver never received the MUSCL-Hancock predictor source term. eq_wb exists in chromosphere.hpp for this solver only — never set it on a release Grid. The mesh-scaled artificial conduction term is available but off unless ISO_NUMERICAL_DIFFUSIVITY_MULT is set, which defaults to 0.

Source files. scenarios/model_column.hpp, scenarios/model_column.cpp, and src/two_fluid/.

model_c7 — quiet-Sun baseline and shared C7 library

Runs the Historical two-fluid solver (non-release). model_c7.cpp also hosts the shared C7 atmosphere library that model_column, model_flare and analytic_canopy draw on.

Field-line geometry. Straight line, B_imh = B_i = B_iph = 1, d(1/B)/ds = 0, gravity on with phi_g gauged to zero at the base. The domain is the Model C7 table from 1003 km to 2153 km (T = 6225 K to 2.31e4 K, the lower transition region) in the default non-extended form. model_c7_ic(Grid and state layout, extended=true) instead runs the full Table 26 up to ~68 Mm unless Grid::corona_top_km truncates it earlier. Faces are uniformly spaced (nF = ns + 5); the default cell count is 100.

Initial condition. Avrett & Loeser (2008) Model C7, Table 26 — height, n_e, n_HI, T. Unlike model_column, the density is taken from the table, not re-integrated: C7 was built with NLTE radiative balance rather than ideal-gas hydrostatic equilibrium, so under this code's EOS the profile is off hydrostatic balance by a nearly uniform 20–26 %. The three tabulated quantities are interpolated onto the faces with a natural cubic spline and floored (n_e >= 1e10, n_n >= 1e8, T >= 3e3) to guard spline overshoot across the steep transition region; cell values are the mean of the bounding faces. Velocities are zero. The Route-B photoionization closure inverts the local ionization balance of exactly the active Stage-E network so the tabulated profile is a fixed point of it, blending above 1500 km (over a 120 km width) to the frozen FAL-C rate of Chae (2021).

Inner boundary (1003 km) — discrete-HSE V = 0 reservoir. rho_i and rho_n are Dirichlet, pinned at the C7 base values captured in the IC. V and U are exactly zero. The ghost pressures are hydrostatic, p_ghost = p_0 + rho_0 g ds_0, so the pressure gradient across the inner face balances gravity discretely and V = U = 0 is an exact fixed point of the momentum update — the base does not launch a wave. Both inner ghosts carry the same state. Nothing on this face is Neumann; the reflecting ghosts that apply_open_bcs writes are fully overwritten.

Outer boundary (2153 km). Two closures exist, and the bare model_c7 scenario selects the second.

  • Default, tr_jump_bc = false — the fixed lower-transition-region RTV reservoir. rho_i, rho_n, T_i and T_n are Neumann (zero-gradient, giving continuous pressure across the constant-pressure TR); V is Mach-capped at Grid::outer_mach_cap * c_s with outer_mach_cap = 0.05, and the neutral is locked to the charged fluid (U = V). The coronal heat enters as an imposed Neumann flux q(T) = (2/7) kappa_0 T_cor^{7/2} / L_cor with kappa_0 = 1e-11 W m^-1 K^-7/2, T_cor = 8e5 K and L_cor = 4.5e7 m, i.e. about 29 W m^-2. impose_outer_heat_flux is gated on radiative cooling — heat is only imposed when there is a sink to balance it. model_flare and analytic_canopy use this closure.
  • tr_jump_bc = true — the hybrid "new explanation" closure that the bare model_c7 scenario sets. The top face imposes a centred hydrostatic ghost pressure p_g = p_lo - 2 ds rho_w g per fluid, an EOS ghost density, and a ghost temperature T_g0 = a T_top, T_g1 = b T_g0. Note that despite the name, C7_TJUMP_A and C7_TJUMP_B both default to 1.0, so the default is a continuous extrapolation and not a temperature jump. Velocity is Mach-capped exactly as above. Coronal heat still enters through the imposed Neumann q(T) — impose_outer_heat_flux is deliberately left untouched here, because on the coarse 100-cell grid the thin rise to ~23 kK is unresolved and any Dirichlet wall hot enough to deliver ~30 W m^-2 over-conducts (kappa_e ~ T^{5/2}) and throws off spurious km/s flows. This branch also sets Grid::well_balanced.

Active physics. Conduction is on (the Grid default; model_c7_ic never touches it). Ionization and radiative cooling come from the command line and are on unless no-ionization / no-cooling is passed. model_c7_ic sets the isotropic grid-scaled numerical diffusivity numerical_diffusivity_per_length = 2e3 m/s, TRAC gated on radiative cooling with trac_T_chrom = 2e4 K, and the vacuum/positivity floor. The adiabatic index is the Grid default gamma_mono = 5/3. model_c7 never loads a Gamma1 table; the driver throws if GAMMA_TABLE is set for any scenario other than model_column.

Source files. scenarios/model_c7.hpp, scenarios/model_c7.cpp, scenarios/scenario.cpp (the shared apply_open_bcs), and src/two_fluid/.

model_flare — explosive evaporation

Runs the Historical two-fluid solver (non-release). It is model_c7 plus a transient beam and an opened top.

Geometry and initial condition. Inherited verbatim from model_c7_ic in its default (non-extended, tr_jump_bc = false) form: straight line, B = 1, 1003 to 2153 km. The cell count is FLARE_NS, default 100 — a finer grid resolves the steep condensation-front contact discontinuity. model_flare_ic forces enable_ionization and enable_radiative_cooling true before calling model_c7_ic, and the order matters because q(T) and TRAC are gated on cooling. The radiative sink is load-bearing rather than decorative: the explosive/gentle threshold is the competition between beam heating and radiative loss. Three-body recombination is likewise required — the explosive condensation is shock-compressed to densities where it is the dominant sink, and without it the ionization fraction drifts and the run goes NaN a few seconds after the beam fires.

Boundaries. The model_c7 RTV reservoir closure, with one change: Grid::outer_free_outflow (from FLARE_FREE_OUTFLOW, default on) lifts the Mach cap at the outer face, leaving the ghost velocity a pure Neumann copy of the top cell so a supersonic evaporation upflow can leave the domain. The Mach-0.05 cap would otherwise choke it. The header notes that a Neumann outflow face is ill-posed for inflow. The inner discrete-HSE V = U = 0 reservoir is unchanged.

Active physics. Everything model_c7 has, plus the nonthermal-electron-beam volumetric heating source: beam_flux from FLARE_BEAM_FLUX, default 5e7 W m^-2 — the Fisher et al. (1985) middle explosive run, well above the threshold F_crit ~ 7e6 W m^-2 — switching on at t = 2 s after about one acoustic time, with a 10 s flat top, 1 s cosine ramps, and a deposition window from 1600 to 2000 km in the upper chromosphere below the transition region. FLARE_DIFF_MULT multiplies the inherited numerical diffusivity.

Source files. scenarios/model_flare.hpp, scenarios/model_flare.cpp, scenarios/model_c7.cpp, src/two_fluid/.

analytic_canopy — exponential magnetic canopy

Runs the Historical two-fluid solver (non-release). It is deliberately the minimal perturbation of model_c7: identical domain, identical thermodynamics, identical gravity, identical ghosts, identical initial condition, and an outer BC that delegates verbatim to model_c7_update_bc (the C7 outer closure depends only on n, T and V, none of which involve B). The only difference is the d(1/B)/ds source term, which makes this the clean way to isolate the effect of flux-tube expansion.

Field-line geometry. analytic_canopy_ic calls model_c7_ic (which leaves B = 1, d(1/B)/ds = 0) and then overwrites the field with the consensus exponential-canopy recipe

B(z) = B_inf + (B_0 - B_inf) * exp(-(z - z_base) / H_B)

with the defaults read from scenarios/analytic_canopy.cpp:

Constant Value Meaning
B_0 1.0e-2 T = 100 G footpoint network flux concentration
B_inf 1.5e-3 T = 15 G canopy-merged chromospheric value
H_B 3.0e5 m = 300 km chromospheric magnetic scale height

The field is vertical, so arc length s equals height above the C7 base. B_imh and B_iph are evaluated at the faces, B_i is their mean, and d(1/B)/ds is the corresponding face difference. Grid::broadcast is re-run so the packed caches stay in sync. The default cell count is 100. References for the parameter choices: Bellot Rubio & Orozco Suárez (2019), Kontar et al. (2008), Martínez-Sykora et al. (2019).

Source files. scenarios/analytic_canopy.hpp, scenarios/analytic_canopy.cpp, scenarios/model_c7.cpp, src/two_fluid/.

pfss_field_line — traced potential-field line

Runs the Historical two-fluid solver (non-release). This scenario requires a data_path — the fifth positional argument to chromo_main — and throws without one.

Field-line geometry. Everything geometric is read from a tabulated data file produced by util/extract_field_line.py, which solves a PFSS extrapolation of a synoptic (GONG / ADAPT-GONG) magnetogram and traces a field line from a chosen footpoint: ds_i, B_imh, B_iph, and both gravity potentials phi_g_imh / phi_g_iph come straight from the file, with B_i their mean and d(1/B)/ds finite-differenced. The cell count ns is read from the file's [META] section before Grid::init. These field lines carry their own externally-specified mesh and never go through the static refinement builder.

Honest caveat on what PFSS does and does not give you. PFSS resolves r in [1, 2.5] R_sun. The entire ~1 Mm chromospheric domain occupies well under a percent of that range and therefore falls inside the first PFSS radial cell, so B(s) within the chromosphere comes out nearly constant. What this scenario legitimately provides is a physically motivated footpoint |B| and the field-line topology (length, inclination, whether the line is open or closed). It does not resolve B(s) inside the chromosphere. For chromospheric canopy expansion below ~1 Mm use analytic_canopy instead. This caveat is stated in util/extract_field_line.py and belongs in any write-up that uses PFSS geometry.

Initial condition. Per-cell n_e, n_n and T are read from the file (the generator samples Model C7 along the trace) with velocities zero; the energies include rho * phi_g so that cons2prim recovers the right pressure. The [GHOSTS] section only seeds the pre-step ghost state — the first update_bc call replaces it. Note that unlike model_c7_ic, pfss_ic does not re-calibrate the background to be a Stage-E fixed point; it uses the scalar fallback photoionization rate, which is adequate for short beam-driven runs but leaves a slow quiet-background ionization drift.

Boundaries — apply_open_bcs. The inner face is always a reflecting wall: cells 0 and 1 are mirrored into the two ghosts with V, U -> -V, -U. The outer face depends on the file's topology field. For closed (half loop, outer face is the apex) and full (whole loop, outer face is footpoint B), Grid::outer_reflecting is set and cells ns-1 and ns-2 are mirrored with reversed velocities, making the face a zero-flux symmetry plane so evaporated plasma is confined and fills the loop. For an open line the outer face is pure Neumann outflow — rho, T, V and U all zero-gradient at both ghosts. That face has no impedance: outgoing waves see a transparent boundary and nothing is specified on the incoming characteristic, which is stable only when the state is near hydrostatic or steady, so transient runs needing boundary damping can go unstable. There is no Mach cap on this face.

Optional physics overlays, both default-off and mutually exclusive in practice:

  • PFSS_FLARE=1 overlays the model_flare physics on this geometry — forces ionization and radiative cooling, adds grid-scaled numerical diffusivity, TRAC and the RTV q(T), and switches on the nonthermal beam. It shares the FLARE_* environment names with model_flare, and additionally defaults to the self-consistent thick-target beam (Emslie 1978), injecting at the loop apex and attenuating down each leg by collisional stopping.
  • GENTLE=1 instead adds the steady footpoint-anchored ambient coronal heating H(s) that a prescribed-temperature loop otherwise lacks, calibrated by inverting the RTV (1978) / Aschwanden & Schrijver (2002) static scaling for the footpoint heating that relaxes a loop of half-length L to a target apex temperature. There is no beam: gentle evaporation is driven by a slow sub-threshold ramp of the heating. Because the corona is heated inside the domain, no boundary q(T) crutch is imposed.

Source files. scenarios/pfss_field_line.hpp, scenarios/pfss_field_line.cpp, scenarios/data_file_parser.hpp, scenarios/data_file_parser.cpp, scenarios/scenario.cpp (apply_open_bcs), util/extract_field_line.py, and src/two_fluid/.
