Yes — this is a real problem. The written scheme is **backward Euler in intention**, but the implementation uses a **plain Picard fixed-point iteration** to approximate the implicit solve:

[
u^{n+1,k+1}
===========

u^n+\Delta t\left(R_E(u^n)+R_I(u^{n+1,k})\right).
]

That only converges when the implicit source is weak enough over one timestep. But here (R_I) contains exactly the stiffest physics: ion-neutral drag, collisional temperature equilibration, and field-aligned heat conduction. The paper also places those terms in (R_I) in Eq. 61 and advances them using Eq. 64. 

The issue is:

[
\text{Backward Euler is stable for stiff terms, but Picard iteration is not automatically stable.}
]

For convergence, the fixed-point map needs roughly

[
\rho\left(\Delta t,\frac{\partial R_I}{\partial u}\right)<1.
]

But in your code, (\Delta t) is chosen from the **hyperbolic CFL**, not from the collision or diffusion timescale. So the explicit part says the timestep is fine, while the Picard implicit solver sees enormous stiffness and diverges.

### What goes wrong physically/numerically

For ion-neutral drag,

[
R_V \sim -\frac{\alpha}{\rho_i}(V-U),
\qquad
R_U \sim +\frac{\alpha}{\rho_n}(V-U).
]

The drift velocity

[
w=V-U
]

relaxes with rate

[
\lambda_{\rm drag}
==================

\alpha\left(\frac{1}{\rho_i}+\frac{1}{\rho_n}\right).
]

So Picard error behaves roughly like

[
e^{k+1}\sim \Delta t,\lambda_{\rm drag},e^k.
]

If (\Delta t,\lambda_{\rm drag}\sim 60), each Picard iteration makes the drift error about 60 times larger. That is divergence, not slow convergence.

The temperature exchange term has the same structure: (T_i-T_n) is a stiff relaxation mode. The heat conduction term is also bad for Picard because diffusion gives eigenvalues of size roughly

[
\lambda_{\rm cond}\sim \frac{\kappa}{\rho c_v \Delta s^2}.
]

So Picard on the diffusion operator behaves like Jacobi iteration on

[
(I-\Delta t D)T^{n+1}=T^*,
]

and it diverges when the diffusion number is larger than order one.

### The core diagnosis

The bug is not that the physics is stiff. The bug is that the code treats stiff physics with a fixed-point iteration that still has a stiffness-dependent convergence limit.

So the current “semi-implicit” method only works when

[
\Delta t
<
\min
\left[
\frac{1}{\lambda_{\rm drag}},
\frac{1}{\lambda_{\rm temp}},
\frac{\rho c_v\Delta s^2}{\kappa}
\right],
]

which defeats the purpose of putting those terms in (R_I).

---

## Recommended solution

Replace the Picard fixed-point map with actual implicit solves for the stiff pieces.

A good practical split is:

[
U^* = U^n + \Delta t,R_E(U^n),
]

then solve the stiff operators implicitly:

[
U^{n+1}
=======

U^*
+
\Delta t,R_I(U^{n+1}).
]

But do **not** solve this using raw Picard. Use specialized implicit solves.

### 1. Solve drag momentum exchange analytically per cell

For each cell, with densities frozen during the source update, solve

[
\frac{V^{n+1}-V^*}{\Delta t}
============================

-\frac{\alpha}{\rho_i}(V^{n+1}-U^{n+1}),
]

[
\frac{U^{n+1}-U^*}{\Delta t}
============================

+\frac{\alpha}{\rho_n}(V^{n+1}-U^{n+1}).
]

This is just a (2\times2) linear system:

[
\begin{bmatrix}
1+\Delta t,\alpha/\rho_i & -\Delta t,\alpha/\rho_i \
-\Delta t,\alpha/\rho_n & 1+\Delta t,\alpha/\rho_n
\end{bmatrix}
\begin{bmatrix}
V^{n+1}\
U^{n+1}
\end{bmatrix}
=============

\begin{bmatrix}
V^*\
U^*
\end{bmatrix}.
]

Even better, use the drift form:

[
w^{n+1}
=======

\frac{w^*}
{1+\Delta t,\alpha\left(\frac{1}{\rho_i}+\frac{1}{\rho_n}\right)}.
]

Then reconstruct (V^{n+1}) and (U^{n+1}) from total momentum conservation:

[
V_{\rm cm}
==========

\frac{\rho_i V^*+\rho_n U^*}{\rho_i+\rho_n},
]

[
V^{n+1}
=======

V_{\rm cm}
+
\frac{\rho_n}{\rho_i+\rho_n}w^{n+1},
]

[
U^{n+1}
=======

## V_{\rm cm}

\frac{\rho_i}{\rho_i+\rho_n}w^{n+1}.
]

This is unconditionally stable for drag and exactly damps the drift.

### 2. Solve temperature equilibration as a local implicit (2\times2) system

For the thermal exchange part, solve something like

[
C_i\frac{T_i^{n+1}-T_i^*}{\Delta t}
===================================

\beta(T_n^{n+1}-T_i^{n+1}) + Q_i,
]

[
C_n\frac{T_n^{n+1}-T_n^*}{\Delta t}
===================================

\beta(T_i^{n+1}-T_n^{n+1}) + Q_n,
]

where

[
\beta=\frac{3k_B\alpha}{m_i+m_n}.
]

Here (C_i) and (C_n) are the heat capacities per volume for the charged and neutral fluids. For your model,

[
C_i \approx 3n_i k_B,
\qquad
C_n \approx \frac{3}{2}n_n k_B,
]

because the charged-fluid pressure includes electrons, (p_i=2n_i k_BT_i), while the neutral pressure is (p_n=n_nk_BT_n). The paper folds electron pressure and heat conduction into the ion/charged-fluid equation using quasi-neutrality. 

This gives another local (2\times2) solve per cell. The frictional heating from the lost drift kinetic energy should be added to the thermal energies in an energy-conserving way.

A robust approach is:

1. Update (V,U) with the implicit drag solve.
2. Compute the lost drift kinetic energy.
3. Add that energy to the ion/neutral thermal pools according to the model’s collisional heating partition.
4. Solve (T_i,T_n) implicitly for temperature equilibration.

### 3. Solve heat conduction with a tridiagonal implicit diffusion solve

Do not Picard-iterate the conduction term pointwise. Assemble the finite-volume diffusion matrix from Eq. 62:

[
C_i =
\frac{B_i}{\Delta s_i}
\left[
\frac{K_{i+1/2}}{B_{i+1/2}}
\frac{T_{i+1}-T_i}{\Delta s_{i+1/2}}
------------------------------------

\frac{K_{i-1/2}}{B_{i-1/2}}
\frac{T_i-T_{i-1}}{\Delta s_{i-1/2}}
\right].
]

This creates a tridiagonal operator in (T). Then solve

[
\left(C_V - \Delta t,L_K\right)T^{n+1}
======================================

C_V T^*,
]

where (L_K) is the discrete conduction operator and (C_V) is the heat capacity per volume.

For nonlinear conductivity, for example (\kappa_e\propto T^{5/2}), use one of these:

* **Lagged conductivity:** compute (K) from (T^*) or (T^n), assemble the matrix, solve once. This is robust and simple.
* **Newton solve:** recompute (K(T)) and include (dK/dT) in the Jacobian.
* **Picard-with-linear-solves:** update (K) from the latest temperature, but each iteration solves the full tridiagonal diffusion matrix. This is very different from raw fixed-point iteration and is much more stable.

For a first fix, use **lagged (K)**. It is usually stable and much easier to implement.

## Minimal code-level structure

The update should look more like this:

```cpp
// 1. Explicit hyperbolic/geometric update
Ustar = Uold + dt * RE(Uold);

// 2. Convert to primitive variables
prim = cons_to_prim(Ustar);

// 3. Local implicit collision solve per cell
for each cell i:
    solve_drag_2x2_or_exact(i, prim, dt);
    solve_temperature_exchange_2x2(i, prim, dt);
    enforce_energy_consistency(i, prim);

// 4. Global implicit heat conduction solve
solve_ion_conduction_tridiagonal(prim.Ti, prim.rhoi, prim.ni, prim.nn, B, dt);
solve_neutral_conduction_tridiagonal(prim.Tn, prim.rhon, prim.ni, prim.nn, B, dt);

// 5. Convert back to conserved variables
Unew = prim_to_cons(prim);
```

A more advanced version would solve collisions and conduction together with Newton:

[
G(U^{n+1})
==========

## U^{n+1}

## U^*

# \Delta t,R_I(U^{n+1})

0.

]

Then use the Jacobian

[
J_G
===

I-\Delta t,\frac{\partial R_I}{\partial U}.
]

That is the cleanest mathematically, but the split method above is much easier and likely sufficient.

## Should you instead reduce the timestep?

You could impose a stiff timestep condition:

[
\Delta t
<
C
\min
\left[
\frac{1}{\alpha(1/\rho_i+1/\rho_n)},
\frac{\rho c_v\Delta s^2}{\kappa}
\right].
]

That would make the current Picard map converge.

But this is not a good solution. In the lower chromosphere and transition region, that timestep may be far smaller than the acoustic CFL timestep. You would lose the whole benefit of an implicit (R_I).

So the right fix is:

**Keep the hyperbolic CFL timestep, but replace Picard evaluation of (R_I) with real implicit solves: local (2\times2) solves for drag and temperature exchange, plus tridiagonal matrix solves for heat conduction.**

In one sentence: the current scheme says “implicit,” but the solver behaves like an unstable fixed-point iteration for stiff source terms; make the implicit part a true backward-Euler solve.
